Live Subs is an experimental iOS 27+ Swift 6 app with a ReplayKit upload extension and sample-buffer Picture in Picture. It streams app audio, not the microphone, to your own Soniox account. API keys stay in a shared Keychain group, never in subtitle archives.

The transcription and translation streams are deliberately independent. Tokens are processed in received order, and each lane closes only on its own finalized boundary. Late translation cannot clear a new source segment, and multiple boundaries in one response produce separate cues. Chinese source speech can be archived without a translation. Soniox does not guarantee one-to-one source/translation token or segment alignment; translation tokens have no timestamps. SRT therefore uses labeled independent original and translation cues, with translation times approximated from receipt time. These may overlap or appear out of timestamp order. The two PiP lines are latest stream text, not a verified aligned sentence pair.

Normal stop first writes a recovery snapshot, sends an empty WebSocket TEXT frame, processes remaining tokens, and waits for finished with a short timeout. It does not reconnect while ending. ReplayKit controls the extension lifetime; the ending callback cannot guarantee final network delivery or disk flush. Finalized tails are archived; partial hypotheses remain explicitly uncertain in recovery JSON. Snapshots are saved as responses arrive, also before reconnect and stop. Recovery export is manual, not automatic replay; after an abrupt crash a pending cue may already be present in SRT, so compare before merging. No audio is retained and lost audio cannot be reconstructed.

App and extension share the same runtime signing resolver. It reads provisioning-profile hints, configured SharedAppGroupCandidates, and a default-Keychain-access-group probe using public SecItem APIs. It validates each candidate through the sandbox container API, then uses the resolved App Group itself as the shared Keychain access group. No SecTask/private entitlement API is used. The default access group supplies only a candidate prefix; it is not assumed to be shared. Key saves Update before Add and report OSStatus errors rather than deleting the previous key.

SideStore can rewrite bundle IDs and App Groups when resigning. Common team-suffixed groups and profile-listed matching groups are considered, but the app cannot enumerate all effective signed entitlements with a public iOS API and cannot fix missing entitlements. Custom resigners may require the same explicit SharedAppGroupCandidates in both Info.plists before signing. If multiple candidates are accessible, they must resolve identically in both processes. The broadcast picker discovers the embedded extension's actual bundle ID instead of constructing it from the parent ID. Existing keys saved by the early hardcoded-group build must be saved again. A container resolving in the app is not proof that the extension has matching permissions.

Build configuration is project.yml for XcodeGen. On a Mac with Xcode, generate the project with xcodegen generate, then build LiveSubs for a generic iOS device with code signing disabled when preparing an unsigned archive for personal signing. The standalone public repository includes an unsigned-device build workflow using the documented xcode-27 hosted image and explicitly selected Xcode 27.2 RC. It prints the actual Xcode and SDK versions and checks for iOS 27.2. A successful CI build does not establish device or signing acceptance. The standalone Foundation core regression suite can run on a Swift toolchain with swiftc Shared/Transcript.swift Tests/CoreTests.swift -o /tmp/live-subs-core-tests followed by /tmp/live-subs-core-tests. It covers late translation, multiple boundaries, untranslated Chinese, partial replacement, independent lanes, uncertain tails, and JSON recovery. Tests/static_checks.py checks source contracts and plists without pretending to compile Swift.

CI compilation status is available in the repository Actions history; this app has not been run on an iPhone. Remaining acceptance includes real SideStore resigning of both targets, shared Keychain read after save/update/relaunch, correct broadcast extension selection, real system-audio capture, PiP lifetime, late translations and stopping during speech, interrupted network, and recovery-file contents. DRM-protected audio may be unavailable. Concurrent video PiP and this PiP may conflict. Atomic text rewrites and per-response JSON snapshots prioritize recoverability but need long-session memory, I/O and performance testing.

Protocol references are https://docs.soniox.com/translation/stt-translation/rt-translation and https://docs.soniox.com/api-reference/stt/websocket-api . Apple's shared-group behavior is documented at https://developer.apple.com/documentation/security/ksecattraccessgroup . SideStore signing caveats are illustrated by https://github.com/SideStore/SideStore/issues/1437 and https://github.com/SideStore/SideStore/issues/1432 . These references do not establish that this build has passed device acceptance.

The build enables Swift 6 language mode with complete strict concurrency checking. Settings state uses a MainActor Observable model. PiP rendering is MainActor-isolated. Socket and transcript callbacks currently use an explicit serial-queue confinement boundary rather than a full actor rewrite; the two queue/ReplayKit bridge classes declare unchecked Sendable with the isolation contract documented in code. This is a limited migration, not a claim that the networking layer already uses actors or async/await throughout. Future macOS 27 work is not included in this iOS app.
